# Lab 04 - E-Commerce Product Entry
PHP 8 + MySQL/MariaDB, PDO prepared statements, server-side validation.

## Files in this folder (only 4)
| File | What it contains |
|---|---|

## Setup (XAMPP on Windows)
1. Start **Apache** and **MySQL** in the XAMPP Control Panel.
2. Copy this folder (`lab04_product_entry`) into `C:\xampp\htdocs\`.
3. Open **http://localhost/phpmyadmin** > **Import** > choose `database.sql` > **Go**. (It creates the database `lab04_shop`; importing twice is safe.)
4. Open **http://localhost/lab04_product_entry/** in the browser.
5. If your MySQL account is not `root` with an empty password, change the `$DB` line at the top of `index.php`.

Requires PHP 8.1+ with `pdo_mysql`, `mbstring` and `fileinfo` (all enabled in XAMPP by default).

## Validation rules
- Product name: 3-100 characters.
- SKU: mandatory, 3-40 characters (letters, digits, - _), stored upper-case, UNIQUE (case-insensitive).
- Category: mandatory (must exist). Unit price (XAF): number greater than zero, max 2 decimals.
- Quantity: whole number, zero or more (negative and decimal values rejected).
- Description: optional, max 1000 characters. "Available for sale": optional checkbox.
- Image (optional): JPEG or PNG only, must be under 2 MB. Checked on the server using the real file content (finfo + getimagesize), not the file name or browser type.
- Stored image reference: random 32-hex name + .jpg/.png generated by the server inside `uploads/`; the client file name/path is never used. `uploads/.htaccess` blocks script execution. If the DB insert fails the stored file is deleted.

All validation runs on the server (the form uses `novalidate` so that the server messages can be demonstrated; browser attributes such as `required`/`type` are kept only to help users). Each field shows its own message and keeps the typed (HTML-escaped) value after a rejected submission.

## Database design
`categories` (lookup, seeded) and `products` (PK `id`, UNIQUE `sku`, FK category, CHECK price > 0, `image_file` = server-generated file name only).

Business rules are enforced twice: by a friendly check in PHP **and** by a database constraint (so a race condition cannot create a bad row).

## Security and reliability
- Every SQL statement uses PDO prepared statements with real server-side preparation (no concatenation of user input).
- All output is escaped with `htmlspecialchars` (XSS); a CSRF token protects the POST.
- "Success" is shown only when the insert returned exactly 1 affected row, followed by a redirect (Post/Redirect/Get) so refreshing does not resubmit.
- Database errors are logged with `error_log` and the user sees a generic message; no SQL or stack trace is exposed (tested with MySQL stopped).

## Assumptions
There is no login page (not requested); in a real shop this page must be behind administrator authentication.
